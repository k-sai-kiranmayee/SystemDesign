RAG with Multi-Modal PDFs
Challenges, Solutions & End-to-End Flow

A comprehensive breakdown of every failure point in traditional RAG when processing PDFs containing text, tables, and images — plus the modern fixes for each.

🔄 End-to-End Pipeline Flow
Complete journey from raw PDF + user query to grounded final answer
1
📥 User Input
Entry point — PDF document & natural language query
What happens
User uploads a PDF (single or batch). Optionally provides metadata (domain, date, language). Submits a natural language query or question.
Inputs
PDF file(s) · User query string · Optional: language hint, page range, document category
Outputs / Next
Validated PDF bytes + query string handed to the ingestion pipeline. Query sent separately to the retrieval pipeline.
2
🔍 PDF Pre-Processing & Classification
Detect PDF type, language, structure before extraction
What happens
Classify PDF: native-text vs scanned (image-only) vs hybrid. Detect document language. Check for encryption/DRM. Identify page count, orientation, multi-column layout.
Tools
pdfjs-dist · pdf-parse · file-type · franc · pdf2pic · pdf-lib
Edge cases handled here
Password-protected PDFs · corrupted files · zero-byte PDFs · PDFs embedded inside PDFs · right-to-left script detection
3
📄 Multi-Modal Content Extraction
Separate extraction paths for text, tables, and images
Text path
Native PDFs: direct text extraction preserving reading order. Scanned PDFs: OCR via tesseract.js / AWS Textract / Azure DI. Post-process: remove headers/footers, fix hyphenation, normalize whitespace, handle footnotes.
Table path
Detect tables (tabula-js, pdf-parse, pdfreader). Extract with structure preserved → convert to Markdown or HTML. Handle merged/spanning cells. Flag multi-page tables for re-assembly.
Image path
Extract embedded images (pdfjs-dist + sharp). Render each page as high-res PNG for layout understanding. Pass images to Vision LLM (openai SDK / @anthropic-ai/sdk) for captioning. Use @xenova/transformers (CLIP) for multi-modal embeddings.
4
✂️ Intelligent Chunking
Content-type-aware chunking — not one-size-fits-all
Text chunking
Semantic chunking using sentence boundaries + embedding similarity (langchain JS / llamaindex). Hierarchical: document → section → paragraph. Overlap = 10–20% for context continuity. Max chunk ≈ 512 tokens. Attach page number + section heading as metadata.
Table chunking
Each table is a single atomic chunk (no splitting). Store full Markdown/HTML table. Add a natural-language summary chunk alongside. Attach column names as searchable metadata.
Image chunking
Each image/figure = one chunk. Store: image ID, page, position, caption (from Vision LLM), surrounding text context. Generate text description embedding. Optionally store @xenova/transformers CLIP visual embedding separately.
5
🧬 Embedding Generation
Convert chunks into dense vectors (text) + multi-modal vectors (images)
Text embeddings
Model: openai (text-embedding-3-large) / @xenova/transformers (BGE-M3, E5-mistral). Domain-specific fine-tuned models for legal/medical/finance PDFs. Normalize vectors. Handle token-limit overflow with sliding window.
Multi-modal embeddings
Image → @xenova/transformers (CLIP / SigLIP). Table → text embedding of Markdown representation. Hybrid: embed image caption as text + store raw visual embedding in separate index.
Metadata schema
{ source_doc, page_num, chunk_type: text|table|image, section_heading, language, creation_date, confidence_score, bounding_box }
6
🗄️ Vector Store Indexing
Separate indexes per content type for precision retrieval
Index architecture
Index 1 (text chunks) — dense + sparse. Index 2 (table chunks) — text embedding. Index 3 (image chunks) — CLIP visual + caption text. Metadata filter layer on top of all indexes.
Storage options
@pinecone-database/pinecone · weaviate-ts-client · @qdrant/js-client-rest · pgvector (pg) · chromadb · hnswlib-node (local). @elastic/elasticsearch for sparse/keyword hybrid. Document store: S3 / local FS for raw chunks.
Indexing metadata
Inverted index on section_heading, page_num, chunk_type for fast metadata filtering. Graph index for cross-reference links (footnotes → main body).
7
❓ Query Processing & Expansion
Transform raw query into an optimized retrieval signal
Query analysis
Classify query intent: factual lookup, table query, visual query, comparative. Detect if it needs data from multiple content types. Detect language mismatch between query and document.
Query expansion
HyDE (Hypothetical Document Embeddings) — generate hypothetical answer, embed it. Multi-query generation: rephrase query 3–5 ways to catch diverse chunks. Synonym expansion for domain terms.
Routing
Route query to correct index(es): "show me the bar chart on page 5" → image index. "revenue table Q3" → table index. General question → text index + optional others.
8
🔎 Hybrid Retrieval
Dense semantic + sparse keyword + metadata-filtered retrieval
Dense retrieval
ANN search (HNSW/IVF) in vector store. Top-K = 20 candidates per index. Cross-encoder reranking (cohere-ai / @xenova/transformers reranker) to get final top-5.
Sparse retrieval
BM25 / TF-IDF keyword search for exact terms, codes, IDs. Combine dense + sparse via RRF (Reciprocal Rank Fusion). Ensures rare but critical terms (product codes, dates) are never missed.
Context assembly
Merge text, table, and image chunk results. De-duplicate overlapping chunks. Order by page position for reading coherence. Attach source citation metadata to each chunk.
9
🤖 LLM Generation
Grounded answer generation with retrieved multi-modal context
Prompt construction
System: "Answer using only the provided context. Cite source pages." Context window: ordered chunks (text + table markdown + image captions). User query appended last. Total ≤ model context limit.
Model selection
Text-only queries → openai SDK (GPT-4o) / @anthropic-ai/sdk (Claude Sonnet). Image-heavy queries → openai SDK multimodal / @anthropic-ai/sdk (Claude Opus vision). Long documents → @google/generative-ai (Gemini 1.5 Pro, 1M token context).
Guardrails
Faithfulness check: verify claims against retrieved chunks. Hallucination detection (langsmith evals / @xenova/transformers NLI). Refuse answer if confidence below threshold. Flag conflicting information across chunks.
10
📤 Response Output & Feedback
Structured answer with citations, confidence, and user feedback loop
Answer structure
{ answer_text, citations: [{ page, chunk_id, excerpt }], confidence_score, source_types_used: [text, table, image], warnings: [] }
Rendering
Tables rendered as HTML tables in UI. Referenced images shown inline with bounding box highlight. Citations shown as clickable page links in original PDF.
Feedback loop
User rates answer (thumbs up/down). Low-rated answers trigger re-ranking log. Periodic fine-tuning of embedder on feedback data. Drift detection if retrieval quality drops over time.
⚠️ Traditional RAG — Challenges by Content Type
What breaks in a naive text-only RAG pipeline when the PDF contains tables and images
📝
Content Type
Text Extraction Failures
  • Scanned PDFs: text is just pixels — naive extraction returns empty or garbage strings.
  • Multi-column layout: text extracted in wrong order (column-1-line-1, column-2-line-1 …).
  • Headers & footers: page numbers and logos injected into every chunk, polluting embeddings.
  • Footnotes & endnotes: appear mid-paragraph, breaking semantic coherence.
  • Ligatures & special chars: fi, fl, ﬁ rendered as unknown bytes, corrupting search.
  • Mathematical equations: LaTeX or MathML rendered as image — completely lost. edge
  • Bidirectional text (RTL): Arabic/Hebrew mixed with English — word order reversed. edge
  • Invisible text layers: some PDFs have hidden text that OCR tools copy but humans never see. rare
📊
Content Type
Table Handling Failures
  • Structure collapse: table becomes a flat stream of cell values — rows/columns lost.
  • Merged cells: column headers spanning 3 columns produce wrong column-to-value mapping.
  • Multi-page tables: header row only on page 1; subsequent pages have orphaned rows. edge
  • Nested tables: tables inside cells — inner table text appended to outer cell. rare
  • Implicit units: "($ thousands)" in header lost; numbers appear without unit context.
  • Tables as images: screenshots of Excel tables — zero text extracted without OCR.
  • Borderless tables: whitespace-aligned tables not detected as tables at all.
  • Rotated tables: 90° landscape tables on portrait pages — text reads sideways. edge
🖼️
Content Type
Image Handling Failures
  • Complete blindness: traditional RAG skips all embedded images — charts, diagrams, photos vanish.
  • Infographics with key data: bar charts, pie charts, trend lines contain quantitative info never indexed.
  • Architectural diagrams: system flows, org charts — critical structural knowledge lost.
  • Figures referenced in text: "see Figure 3" — figure never retrieved, answer is incomplete.
  • Logos as company identifiers: document provenance lost if logo is the only brand signal. rare
  • Handwritten annotations: sticky notes, margin scribbles — OCR + vision needed. edge
  • Watermarks: overlay text confuses OCR, degrading extracted text quality. edge
  • QR codes & barcodes: embedded product/asset IDs never decoded. rare
✂️
Pipeline Stage
Chunking Strategy Failures
  • Fixed-size chunking splits sentences: cuts mid-thought, destroying local semantic context.
  • Tables split across chunks: header in chunk N, data rows in chunk N+1 — both useless alone.
  • Chunk overlap pollution: overlap duplicates near-identical content, boosting irrelevant results.
  • Long section headers: a heading with no body text becomes a low-signal standalone chunk.
  • Very long paragraphs: a single paragraph exceeds token limit — truncated mid-sentence. edge
  • Dense legal boilerplate: repetitive disclaimer text floods top-K with low-value chunks. edge
  • Cross-references lost: "see Appendix B, Section 4.2" context lost if Appendix is in a different chunk cluster. rare
🧬
Pipeline Stage
Embedding & Retrieval Failures
  • Semantic mismatch for tables: text embeddings can't encode tabular row-column relationships.
  • Domain OOV terms: niche jargon (legal codes, drug names) under-represented in general embeddings.
  • Multilingual document: English query can't retrieve a chunk in French/German. edge
  • Numeric queries: "revenue in 2022" — numbers poorly captured by standard text embeddings.
  • Lexical gaps: user says "profit" but document says "net income" — semantic gap exists.
  • Embedding model token limit: 512-token cap truncates long chunks silently. edge
  • Stale index: document updated but index not refreshed — old chunks returned. rare
  • Near-duplicate documents: two versions of same PDF both indexed → duplicate context window. rare
🤖
Pipeline Stage
LLM Generation Failures
  • Lost-in-the-middle: LLM ignores middle chunks when context window is long.
  • Context window overflow: too many retrieved chunks exceed model limit — some truncated.
  • Hallucination on gaps: if no chunk answers the question, LLM fabricates an answer.
  • Table reasoning errors: LLM misreads Markdown table column alignment, gives wrong value.
  • Conflicting information: two chunks disagree — LLM picks one without flagging conflict. edge
  • Time-sensitive data: old document chunk returned; LLM presents stale figure as current. edge
  • Citation fabrication: LLM cites "page 7" but the relevant data is actually on page 12. rare
  • Language mismatch in generation: doc is in German, query English — LLM may respond in German. rare
✅ Solutions — Traditional vs Modern Multi-Modal RAG
Side-by-side comparison of what breaks and how it's fixed

Table structure Flattened to unordered text stream Structured table extraction → Markdown/HTML + NL summary stored as twin chunks tabula-js, pdf-parse, pdfreader Critical fix
Images / charts Completely ignored Vision LLM generates caption + description; CLIP embedding for visual search openai SDK (GPT-4o), @anthropic-ai/sdk, @xenova/transformers Critical fix
Multi-column layout Wrong reading order — garbled paragraphs Layout-aware extraction with bounding box ordering pdfjs-dist, unstructured-client, pdf-parse High fix
Header / footer noise Repeating boilerplate in every chunk Detect and strip recurring text patterns across pages pdf-parse, custom heuristics High fix

Multilingual docs English query can't retrieve non-English chunks Multilingual embeddings + cross-lingual retrieval @xenova/transformers (mE5, LaBSE, multilingual BGE) High fix

🧪 Edge Cases & Rare Scenarios
Scenarios that most RAG tutorials skip — but production systems will encounter
HIGH
🔒
Password-Protected PDF
Extraction silently fails or throws. Need upfront detection and user prompt for password, or skip + log.
HIGH
🔁
Multi-Page Tables (Continued)
Header row only appears on page 1. Pages 2–N have orphaned data rows with no column context. Must re-assemble table across pages.
HIGH
🌍
Mixed-Language Document
English report with German appendix and French executive summary. Standard embedding models fail cross-lingual retrieval.
HIGH
🖼️
Tables Rendered as Images
Excel screenshots pasted into PDF. Zero text extraction without OCR. Must detect and route to vision model.
MED
🔄
Duplicate PDF Versions
v1 and v2 of same report both indexed. Query retrieves conflicting figures from both. Need content-hash dedup or version tagging.
MED
📐
Rotated / Landscape Pages
Tables or diagrams on 90° rotated pages. Most parsers read text upside-down. Need rotation detection and correction.
MED
⚔️
Conflicting Figures in Same Doc
Executive summary says "revenue $5M", appendix table says "$4.8M". LLM must surface conflict, not silently pick one.
MED
📅
Time-Sensitive Data
Old annual report indexed. Query asks for "current" figures. Must attach document date metadata and warn when data is stale.
MED
∑
Mathematical Equations
LaTeX or MathML equations rendered as images in PDF. Content completely lost to text extraction. Needs Mathpix API or mathjs post-processing.
MED
📜
Legal Boilerplate Flood
100-page contract with 60 pages of identical disclaimers. Top-K retrieval dominated by boilerplate. Need dedup or section exclusion.
LOW
📄
PDF-within-PDF (Embedded)
Some PDFs embed another PDF as an attachment. Standard parsers miss the inner document entirely.
LOW
🖊️
Handwritten Annotations
Margin notes and sticky annotations in scanned docs. Standard OCR misses cursive. Needs handwriting-specific model.
LOW
💧
Watermarked Documents
Semi-transparent "DRAFT" or "CONFIDENTIAL" overlay degrades OCR accuracy on underlying text.
LOW
🔗
Cross-Document References
"See Report B, Table 4.1" — referenced document not in the indexed corpus. Need graph-based cross-doc retrieval or graceful handling.
LOW
🧾
Fillable Form Fields
PDF forms with AcroFields. Filled values stored separately from visible text layout. Standard extraction misses form data.
LOW
👁️
Hidden / Invisible Text Layer
OCR-generated PDFs have transparent text behind images. Can be copied programmatically but never intended to be visible.
🏗️ Recommended Architecture Summary
The three parallel tracks that replace a single text pipeline
📝
Track 1
Text Pipeline
  • Extract: pdf-parse / pdfjs-dist + tesseract.js OCR fallback
  • Clean: strip headers/footers, fix reading order
  • Chunk: semantic chunking (sentence boundary + cosine split)
  • Embed: openai SDK (text-embedding-3-large) / @xenova/transformers (BGE-M3)
  • Index: @qdrant/js-client-rest dense + @elastic/elasticsearch sparse
  • Retrieve: Hybrid RRF + cohere-ai rerank
📊
Track 2
Table Pipeline
  • Detect: tabula-js + custom layout detection
  • Reconstruct: merge multi-page tables, fix merged cells
  • Represent: Markdown + HTML + NL summary twin chunk
  • Embed: embed both Markdown and NL summary
  • Index: separate table index with column name metadata
  • Retrieve: query routed to table index for numeric/aggregate Qs
🖼️
Track 3
Image Pipeline
  • Extract: pdfjs-dist page render + sharp (PNG conversion)
  • Describe: openai SDK / @anthropic-ai/sdk vision → structured caption JSON
  • Embed: openai SDK caption embedding + @xenova/transformers CLIP visual
  • Index: multi-modal vector index (weaviate-ts-client multimodal)
  • Retrieve: text-to-image or image-to-image similarity
  • Return: image thumbnail + caption + page reference in answer
