Module 2
Architecture · Forward Pass (Both Phases)
Technical Architecture
Describes the forward pass — the internal pipeline every transformer runs. This same pipeline executes in both training and inference; it is not exclusive to either.
Architecture · Both Phases Tokenize (text → token IDs) → Static embedding lookup (token ID → vector, no attention yet) → Positional encoding → Self-Attention blocks (Q/K/V, where tokens first see each other) → FFN layers → Final linear projection → Logits
Architecture · Both Phases Model types: Encoder-only (BERT — bidirectional, for classification/embeddings)  ·  Decoder-only (GPT/Llama — causal, for generation)  ·  Encoder-Decoder (T5 — seq2seq, for translation/summarisation)
Training diverges after logits → loss → backprop → weight update  |  Inference diverges after logits → sampling → output token
Module 3
Inference / Output Phase
API Integration & Prompt Engineering
How to consume a trained, frozen model. No weight changes happen here — this is entirely about steering the model's output at runtime.
Inference API request/response flow, message roles (system / user / assistant), parameters (temperature, max_tokens, top_p, frequency_penalty), streaming token-by-token output
Inference Prompt engineering — system prompts, few-shot examples, Chain-of-Thought (CoT), ReAct pattern, output format control
Module 4
Inference / Output Phase
RAG & LangChain
Augmenting a frozen model with external knowledge at runtime — no retraining, no weight updates.
Inference · Indexing (offline prep) Chunk documents → run through encoder model (bidirectional Transformer) → produce contextual vectors → store in vector DB (Pinecone, Chroma, pgvector)
Inference · Per request Embed user query → cosine similarity search → retrieve top-K chunks → inject into prompt → LLM generates grounded answer. LangChain LCEL chains, output parsers, memory, RAGAS evaluation
Module 5
Inference / Output Phase
Agentic AI & Multi-Agent Systems
Multi-step inference on a frozen model — the model reasons and calls tools across many forward passes to complete a task.
Inference ReAct loop — Thought → Action → Observation, repeated until task complete. Each iteration is one inference call. Function/tool calling (model outputs structured JSON to invoke tools)
Inference Planning strategies (CoT, Tree-of-Thought)  ·  LangGraph stateful workflows (nodes = LLM calls, edges = routing logic)  ·  Multi-agent orchestration (orchestrator + specialist agents)
Module 6
Inference / Output Phase
Production: LangSmith, MCP & A2A
Wraps and observes inference in production — tracing calls, connecting agents to data, and coordinating multi-agent systems. Model weights are not touched here.
Inference LangSmith — trace every LLM call, inspect inputs/outputs, measure latency, run evaluations on production traffic
Inference MCP (Model Context Protocol) — standardised way for agents to access external data sources (files, databases, APIs) during inference  ·  A2A Protocol — agent-to-agent communication, task handoff, capability discovery
Module 7
Training Phase
Open Source & Fine-Tuning
The only module entirely in the training phase — every technique here modifies or adapts model weights.
Training HuggingFace ecosystem (Hub, Transformers.js, datasets, pipeline API)  ·  SFT — supervised fine-tuning on (instruction, response) pairs: forward pass → cross-entropy loss → backprop → weight update
Training LoRA / QLoRA — freeze base weights, train small low-rank adapter matrices only (much cheaper)  ·  Quantization (INT8/INT4/GPTQ/GGUF) — compress weights for faster inference after training  ·  RLHF / DPO — alignment: train reward model from human preferences, fine-tune policy model

Trends & Emerging Architectures
What's happening right now — the architectural shifts replacing classic transformers, and the reasoning models changing how we think about LLM output.

Training Reasoning models (o1/o3/DeepSeek-R1) · SLMs (small language models) · Multi-modal LLMs · Modern alignment — GRPO / RLVR replacing PPO
