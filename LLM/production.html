LangSmith, MCP & A2A Protocols

Observe, debug and evaluate agents with LangSmith. Connect models to external data via MCP. Coordinate agents with the A2A protocol. Wraps up the full stack from Module 5.

1
LangSmith — Observability for LLM Apps
Tracing · Evals · Datasets · Prompt management

LangSmith is LangChain's observability platform for LLM applications. Every LLM call, tool invocation, and chain step is captured as a hierarchical run trace you can inspect, compare, and evaluate.

🔍
Tracing
Automatic capture of inputs, outputs, latency, and token counts for every step in your LangChain/LangGraph app. Zero-code setup via env vars.
📊
Evaluations
Run automated evals over a dataset. Compare prompt versions. Detect regressions. LLM-as-judge or custom Python evaluators.
📁
Datasets
Curate labelled examples from production traces. Build golden test sets. Replay runs for regression testing across model versions.
✏️
Prompt Hub
Version and manage prompts centrally. Pull prompts by name in code (pull("my-prompt:v2")). A/B test variants. Non-engineers can iterate prompts without code deploys.
🧪
Playground
Replay any production trace with modified prompts/models interactively. Immediately see how changes affect output without deploying code.
📈
Monitoring
Live dashboards for token usage, latency percentiles (p50/p95/p99), error rates, and feedback scores by tag, project, and model version.
LangSmith Setup & TracingJS
// 1. Enable tracing via environment variables (no code changes needed)
// LANGCHAIN_TRACING_V2=true
// LANGCHAIN_API_KEY=lsv2_pt_xxxxxxx
// LANGCHAIN_PROJECT=my-rag-app  ← groups traces by project

// All LangChain/LangGraph calls are now automatically traced.
// View at: https://smith.langchain.com

// 2. Add custom metadata to traces
import { traceable } from "langsmith/traceable";

const myTracedFunction = traceable(
  async (question: string) => {
    const result = await ragChain.invoke(question);
    return result;
  },
  {
    name: "rag-query",
    run_type: "chain",
    tags: ["production", "v2"],
    metadata: { user_tier: "enterprise" },
  }
);

// 3. Attach user feedback to a run
import { Client } from "langsmith";
const client = new Client();

await client.createFeedback(run_id, "thumbs", {
  score:   1,       // 1 = 👍, 0 = 👎
  comment: "Perfect answer, saved me an hour",
});
LangSmith Evaluation over a DatasetJS
import { evaluate }             from "langsmith/evaluation";
import { LangChainStringEvaluator } from "langchain/evaluation";

// Target function to evaluate
const target = (input) => ragChain.invoke(input.question);

// Evaluators
const exactMatch = ({ outputs, referenceOutputs }) =>
  outputs.answer === referenceOutputs.answer ? { key: "exact_match", score: 1 } : { key: "exact_match", score: 0 };

const evalResult = await evaluate(target, {
  data:       "my-qa-dataset",  // dataset name in LangSmith
  evaluators: [exactMatch],
  experimentPrefix: "rag-v2",
  maxConcurrency: 4,
});
// Results appear in LangSmith UI under Experiments
💡 Simple: LangSmith is the flight recorder for your LLM app. Every prompt, response, latency, and token count gets logged as a trace. When something breaks in production — wrong answer, unexpected tool call, cost spike — you open LangSmith and see exactly what happened at each step. Evaluation datasets let you run regression tests after model or prompt changes.

Model Context Protocol (MCP) — Fundamentals
Standardised interface: AI models ↔ external data & tools

MCP (Model Context Protocol) is an open standard (by Anthropic) that defines how AI models connect to external data sources, tools, and services — using a consistent client-server protocol instead of bespoke integrations.

MCP Architecture:

  ┌─────────────────────────────────────────────────────────────┐
  │                    HOST APPLICATION                          │
  │  ┌──────────────┐        ┌───────────────────────────────┐  │
  │  │   AI Model   │        │         MCP CLIENT            │  │
  │  │  (Claude /   │◀──────▶│  manages connections,         │  │
  │  │   GPT-4 /    │        │  protocol, tool discovery      │  │
  │  │   local)     │        └──────────┬────────────────────┘  │
  │  └──────────────┘                   │  MCP Protocol          │
  └─────────────────────────────────────┼─────────────────────────┘
                                        │  (JSON-RPC 2.0 over stdio/SSE)
              ┌──────────────┬──────────┴──────────┬──────────────┐
              ▼              ▼                      ▼              ▼
        ┌──────────┐  ┌──────────┐           ┌──────────┐  ┌──────────┐
        │MCP Server│  │MCP Server│           │MCP Server│  │MCP Server│
        │ (Files)  │  │ (GitHub) │           │(Postgres)│  │ (Slack)  │
        └──────────┘  └──────────┘           └──────────┘  └──────────┘

Each MCP Server exposes:
  Resources  — read-only data (files, DB records, web pages)
  Tools      — executable functions (write file, run query, send message)
  Prompts    — reusable prompt templates with arguments
📄
Resources
URI-addressable read-only data. file://path/to/doc, db://table/row, git://repo/branch/path. Model reads context from resources.
🔧
Tools
Functions the model can call: create_file, run_sql_query, send_slack_message. Each tool has a JSON Schema for arguments — same as OpenAI function calling.
💬
Prompts
Server-defined prompt templates with arguments. Model requests "code_review" prompt with {language:"TypeScript", style:"strict"} — server returns the rendered system prompt.
💡 Simple: MCP is a USB-C standard for connecting AI models to data sources and tools. Before MCP, every app needed a custom integration for every tool. With MCP, any MCP-compatible model can use any MCP-compatible server — GitHub, databases, file systems — with zero custom glue code. Build the server once, and it works with all MCP clients.
3
Building an MCP Server
Define tools & resources, expose via stdio or HTTP/SSE
MCP Server (Node.js — @modelcontextprotocol/sdk)JS
import { Server }        from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { ListToolsRequestSchema, CallToolRequestSchema } from "@modelcontextprotocol/sdk/types.js";

const server = new Server(
  { name: "my-db-server", version: "1.0.0" },
  { capabilities: { tools: {}, resources: {} } }
);

// Declare available tools
server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [{
    name: "run_query",
    description: "Execute a read-only SQL query against the analytics database",
    inputSchema: {
      type: "object",
      properties: {
        sql:    { type: "string", description: "SQL SELECT statement" },
        limit:  { type: "number", description: "Max rows", default: 100 },
      },
      required: ["sql"],
    },
  }],
}));

// Handle tool calls
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === "run_query") {
    const { sql, limit = 100 } = request.params.arguments;
    const rows = await db.query(sql, limit);  // your DB client
    return { content: [{ type: "text", text: JSON.stringify(rows, null, 2) }] };
  }
  throw new Error("Unknown tool");
});

// Start server (communicates via stdin/stdout)
const transport = new StdioServerTransport();
await server.connect(transport);
// Run as: node server.js  (Claude Desktop / Claude Code auto-starts it)
MCP Client — Connect to a serverJS
import { Client }               from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport }  from "@modelcontextprotocol/sdk/client/stdio.js";

const client = new Client({ name: "my-client", version: "1.0.0" }, { capabilities: {} });

const transport = new StdioClientTransport({
  command: "node", args: ["./my-db-server.js"],
});
await client.connect(transport);

// Discover tools
const { tools } = await client.listTools();
console.log(tools.map(t => t.name));  // ["run_query"]

// Call a tool
const result = await client.callTool({
  name: "run_query",
  arguments: { sql: "SELECT * FROM orders WHERE status='pending' LIMIT 5" },
});
console.log(result.content[0].text);  // JSON rows
MCP Transport Options:

  stdio (default)     — subprocess communication; Claude Desktop uses this
                        simple, secure (isolated process), local only

  HTTP + SSE          — server-sent events for streaming; supports remote MCP servers
                        GET  /sse         → opens SSE stream (server→client)
                        POST /message     → client sends requests

  WebSocket (planned) — bidirectional streaming; better for high-frequency updates
💡 Simple: You define tools (functions the model can call), resources (data the model can read), and prompts (templates the model can request). The server communicates via stdio for local use or HTTP+SSE for remote. Once deployed, any MCP client discovers your tools automatically — no per-client integration code needed.

MCP Configuration & Claude Desktop
claude_desktop_config.json — connecting models to servers

Claude Desktop (and Claude Code) auto-launch MCP servers defined in claude_desktop_config.json. Each server entry specifies how to start it and any environment variables it needs.

claude_desktop_config.jsonJSON
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me/projects"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "ghp_xxxxxxxx" }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": { "POSTGRES_URL": "postgresql://user:pass@localhost:5432/mydb" }
    },
    "my-custom-server": {
      "command": "node",
      "args": ["/path/to/my-mcp-server/index.js"],
      "env": { "API_KEY": "sk-xxxx" }
    }
  }
}

Agent-to-Agent (A2A) Protocol
Google's open standard for inter-agent communication

A2A (Agent-to-Agent) is Google's open protocol for agents to discover, communicate with, and delegate to other agents across different frameworks and vendors. Where MCP connects agents to data/tools, A2A connects agents to other agents.

A2A vs MCP:
  MCP:  Model ←→ Data/Tools (filesystem, DB, APIs)
  A2A:  Agent ←→ Agent      (peer coordination, delegation)

A2A Core Concepts:

  Agent Card (/.well-known/agent.json)
  ┌────────────────────────────────────────────────────────────┐
  │  {                                                          │
  │    "name": "ResearchAgent",                                 │
  │    "description": "Searches and summarises web content",   │
  │    "capabilities": ["text-generation", "web-search"],       │
  │    "skills": [{ "id": "summarise", "description": "..." }],│
  │    "url": "https://agents.company.com/research",            │
  │    "authentication": { "schemes": ["bearer"] }              │
  │  }                                                          │
  └────────────────────────────────────────────────────────────┘

  Task Lifecycle:
  submitted → working → (input-required →) completed / failed / cancelled

  Communication: JSON-RPC 2.0 over HTTP
    tasks/send          — fire a task at an agent
    tasks/sendSubscribe — streaming SSE updates (long-running tasks)
    tasks/get           — poll task status
    tasks/cancel        — abort a task
A2A Task Communication (JS)JS
// Caller agent delegates to a remote specialist agent via A2A
const delegateToResearchAgent = async (query: string) => {
  const task = {
    jsonrpc: "2.0",
    method: "tasks/send",
    id: crypto.randomUUID(),
    params: {
      id: crypto.randomUUID(),
      message: {
        role:  "user",
        parts: [{ type: "text", text: query }],
      },
    },
  };

  const response = await fetch("https://agents.company.com/research", {
    method:  "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": `Bearer ${process.env.AGENT_TOKEN}`,
    },
    body: JSON.stringify(task),
  });

  const result = await response.json();
  // result.result.status = { state: "completed" }
  // result.result.artifacts = [{ parts: [{ type: "text", text: "Summary..." }] }]
  return result.result.artifacts[0].parts[0].text;
};

// Streaming long-running A2A task with SSE
const streamingTask = async (query: string) => {
  const res = await fetch("https://agents.company.com/research", {
    method: "POST",
    headers: { "Content-Type": "application/json", "Authorization": "Bearer ..." },
    body: JSON.stringify({ jsonrpc: "2.0", method: "tasks/sendSubscribe", ... }),
  });
  for await (const event of parseSSE(res.body)) {
    console.log("status update:", event.data.status.state);
  }
};
A2A Multi-Agent Coordination Pattern:

  User Request
       │
       ▼
  ┌──────────────────┐
  │  Orchestrator    │ — reads Agent Cards of available agents
  │  Agent           │
  └────┬─────────────┘
       │ A2A tasks/send
   ┌───┼────────────────────┐
   ▼   ▼                    ▼
[Research  [Code Executor  [Report Writer
 Agent]     Agent]          Agent]
       │                    │
       └──── handoff ───────▶
             (artifact from ResearchAgent fed as input to ReportWriter)
💡 Simple: A2A lets agents built by different teams or frameworks collaborate. Each agent publishes an Agent Card (its API contract). A client sends a task, the server agent processes it and streams progress back via SSE, then returns a final artifact. Think of it as HTTP for AI agents — a standard handshake so any two agents can work together.

Production Best Practices
Reliability · Cost · Security · Latency

Reliability:

  • Exponential backoff + jitter on 429/5xx responses (see Module 3)
  • Fallback models: if GPT-4o fails, fall back to GPT-4o-mini or claude-sonnet
  • Circuit breaker: after N consecutive failures, short-circuit for T seconds
  • Timeout per node: agent nodes should have 30s timeouts to prevent blocking
  • Idempotent tool calls: safe to retry; log tool call IDs to prevent duplicate actions

Cost Control:

  • Model routing: classify query complexity → use cheap model for simple queries
  • Caching: semantic caching (GPTCache / langchain-cache) on frequent identical queries
  • Prompt compression: LLMLingua to compress long contexts by 3–5× without quality loss
  • Streaming: stream to users immediately; don't buffer full response before sending
  • Budget alerts: set spend alerts on OpenAI/Anthropic dashboards; programmatic token budgets

Security:

  • Never log raw prompts to application logs (PII leakage)
  • Input sanitisation: strip injection patterns before sending to LLM
  • Output filtering: scan LLM output for PII/secrets before returning to user
  • Tool least-privilege: read-only tools separate from write tools; human approval on destructive ops
  • API key rotation: rotate LLM provider keys on a schedule; use secrets manager

Latency Optimisation:

  • Parallel retrieval: retrieve from multiple stores concurrently with Promise.all
  • Streaming first token: stream partial responses; user sees output in <1s
  • KV cache reuse: put stable system prompt first; it's cached across requests (OpenAI prompt caching)
  • Batch embeddings: embed chunks in batches of 100 during indexing (not 1-by-1)
  • Edge deployment: deploy LLM proxy close to users (Cloudflare AI Gateway, Vercel AI)
💡 Simple: Production checklist: structured logging + LangSmith traces for every request, per-feature cost tracking (so you know which feature costs $0.50/call), input/output validation at system boundaries, semantic caching for repeated similar queries, and circuit breakers that fall back to a cheaper model when the primary is slow or overloaded.

Edge Cases & Failure Modes
Production pitfalls that are hard to find in development
HIGH
🔑
API Key Leaked in Traces
LangSmith traces capture all message content. If a user sends their API key as a message, it appears in LangSmith plaintext — accessible to all project members.
Use LangSmith masking rules. Never log user messages verbatim. Add PII detection before tracing.
HIGH
⏱️
MCP Server Startup Latency
Claude Desktop starts MCP servers on first use. A slow-starting server (e.g., JVM, slow network init) causes a 10-30s pause on first tool call.
Warm up MCP servers eagerly on host startup. Use keep-alive pings. Prefer Node.js/Go servers for fast cold start.
HIGH
🌐
A2A Agent Discovery Staleness
Agent Cards cached by orchestrator. Remote agent updates its capabilities (new skills, deprecated endpoints) but orchestrator still uses old card — calls fail.
TTL on agent card cache (5–15 min). Re-fetch on 404/501 errors. Agents should version their cards.
MED
🔄
LangSmith Trace Sampling
High-volume production apps send millions of traces. LangSmith costs spike; UI slows. Disabling tracing removes observability entirely.
LANGCHAIN_TRACING_SAMPLE_RATE=0.1 (trace 10%). Always trace errors (LANGCHAIN_TRACING_ON_ERROR=true). Tag and filter by importance.
MED
📦
MCP Resource Over-Exposure
Filesystem MCP server given access to "/" — model can read /etc/passwd, SSH keys, or .env files containing credentials.
Restrict allowed paths in server config. Use allowlist (not denylist). Audit MCP server permissions as part of deployment review.
MED
💸
Eval Runaway Costs
LLM-as-judge evaluations run GPT-4 on every trace. A 10,000-run evaluation dataset × judge call = massive cost. Triggered accidentally via CI/CD.
Use cheaper judge models (GPT-4o-mini). Set maxConcurrency and total eval budget. Gate evals behind explicit deployment approval step.
💡 Simple: Three common production failures: (1) MCP tool schema drift — your tool changed but Claude's cached description did not; restart the MCP server. (2) A2A without authentication — never expose agent task endpoints publicly without auth tokens. (3) Eval cost shock — running GPT-4 as judge on every evaluation gets expensive fast; use GPT-4o-mini and batch evaluations.
