Module 3 — API & Prompts

API Integration & Prompt Engineering

Calling the ChatGPT API from JavaScript, understanding every parameter, building applications, and mastering prompt techniques that reliably steer model behaviour.

1
ChatGPT API — Full Request/Response Flow
From JavaScript code to model output — every layer explained
Your Code
   │  POST /v1/chat/completions
   │  Headers: Authorization: Bearer sk-...
   │  Body: { model, messages, temperature, max_tokens, ... }
   ▼
OpenAI API Gateway
   │  Auth check → rate-limit check → token count check
   ▼
Model Inference (GPU cluster)
   │  Tokenise messages → forward pass → sample → detokenise
   ▼
Response
   │  { id, object, created, model,
   │    choices: [{ message: { role, content }, finish_reason }],
   │    usage: { prompt_tokens, completion_tokens, total_tokens } }
   ▼
Your Code  →  response.choices[0].message.content
Basic API call (JavaScript) JS
// npm install openai
import OpenAI from "openai";

const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

const response = await client.chat.completions.create({
  model:             "gpt-4o",
  messages: [
    { role: "system", content: "You are a helpful assistant." },
    { role: "user",   content: "Explain transformers in 2 sentences." },
  ],
  temperature:       0.7,
  max_tokens:        200,
  top_p:             0.9,
  frequency_penalty: 0.0,
  presence_penalty:  0.0,
});

const answer = response.choices[0].message.content;
const finish = response.choices[0].finish_reason;  // "stop" | "length" | "tool_calls"
const tokens = response.usage.total_tokens;

All parameters explained:

ParameterTypeWhat it controlsTypical value
modelstringWhich model to call"gpt-4o", "gpt-4o-mini"
messagesarrayConversation history (system, user, assistant turns)Required
temperature0–2Randomness of output. 0 = near-deterministic0.7 creative, 0.2 factual
max_tokensintMax output tokens. Model stops when hit.512–4096
top_p0–1Nucleus sampling threshold. Use OR temperature, not both.0.9
frequency_penalty-2 to 2Penalises tokens proportionally to how often they've appeared. Reduces repetition.0–0.5
presence_penalty-2 to 2Flat penalty if token appeared at all. Encourages new topics.0–0.5
stopstring/arrayStop generation when this string is encountered["\n\n", "END"]
seedintAttempt reproducibility (not guaranteed)42
response_formatobjectForce JSON output: {"type":"json_object"}—
streamboolServer-sent events — tokens arrive as they're generatedfalse
💡 Simple: You POST a JSON with your conversation and settings, a GPU runs inference, and you get tokens back. The three controls you'll touch most: temperature (creativity knob), max_tokens (output length cap), and top_p (vocabulary range). Always check finish_reason — if it says "length", your response was silently cut off mid-sentence.

Message Roles & Multi-Turn Conversations
system / user / assistant — how the conversation context is built
messages = [
  { role: "system",    content: "You are a Python expert..." }   ← persistent instruction
  { role: "user",      content: "How do I read a CSV?" }         ← human turn 1
  { role: "assistant", content: "Use pandas: pd.read_csv(…)" }   ← model turn 1
  { role: "user",      content: "What about large files?" }      ← human turn 2
]
↓
Model sees ALL messages as context and responds to the last user turn.

System role:
  - Sets behaviour, persona, output format, constraints
  - Processed first; has strong influence
  - Not shown to end user in typical chat apps

Context window fills up as conversation grows:
  Strategy: trim oldest messages, or summarise them
Streaming responses JS
// Tokens arrive in real-time — better UX for long outputs
const stream = await client.chat.completions.create({
  model:    "gpt-4o",
  messages: [{ role: "user", content: "Write a poem about AI." }],
  stream:   true,
});

for await (const chunk of stream) {
  const delta = chunk.choices[0]?.delta?.content;
  if (delta) process.stdout.write(delta);
}
Structured JSON output JS
// Force JSON-parseable response
const response = await client.chat.completions.create({
  model: "gpt-4o",
  messages: [
    { role: "system", content: "Respond only with valid JSON." },
    { role: "user",   content: "Extract: name, age from 'Alice is 30 years old'." },
  ],
  response_format: { type: "json_object" },
});

const data = JSON.parse(response.choices[0].message.content);
// { name: "Alice", age: 30 }
💡 Simple: system = your standing instructions — persona, rules, output format. user = what the human typed. assistant = what the model replied last time. The model sees the entire array on every single call — there is no built-in memory. You maintain conversation history yourself and pass it each time.
3
Prompt Engineering
Techniques to reliably steer model behaviour — from zero-shot to ReAct
0️⃣
Zero-Shot
Give the task directly with no examples. Works well for simple, clear instructions. Model relies entirely on pre-training.
🔢
Few-Shot
Provide 2–5 input/output examples before the real query. Dramatically improves performance on formatting, classification, or domain-specific tasks.
🔗
Chain-of-Thought (CoT)
Ask the model to "think step by step" before answering. Forces intermediate reasoning. Improves math, logic, multi-step problems significantly.
⚛️
ReAct
Reason + Act loop. Model alternates: Thought → Action (tool call) → Observation → next Thought. Used heavily in agents (Module 5).
Few-shot prompting example JS
const messages = [
  { role: "system",    content: "Classify sentiment as Positive, Negative, or Neutral." },
  // Few-shot examples
  { role: "user",      content: "I love this product!" },
  { role: "assistant", content: "Positive" },
  { role: "user",      content: "This is the worst thing ever." },
  { role: "assistant", content: "Negative" },
  // Real query
  { role: "user",      content: "It's okay, nothing special." },
];
// Model reliably responds: "Neutral"
Chain-of-Thought prompting JS
const messages = [
  {
    role: "system",
    content: "You are a math tutor. "
           + "Think through the problem step by step before giving the final answer. "
           + "End with 'Answer: <number>'",
  },
  {
    role: "user",
    content: "A shop sells 3 types of fruit. Apples cost $1.20, oranges $0.80, "
           + "bananas $0.50. If I buy 4 apples, 3 oranges, and 5 bananas, what's my total?",
  },
];
// Model: "4×1.20 = 4.80, 3×0.80 = 2.40, 5×0.50 = 2.50. Total = 9.70. Answer: 9.70"

Advanced prompt patterns:

PatternWhen to useKey instruction
Self-consistencyAmbiguous reasoning tasksGenerate N answers with high temperature, pick majority vote
Tree of Thought (ToT)Complex multi-path problems"Explore multiple approaches. Evaluate each. Pick the best."
Role promptingDomain expertise needed"You are a senior DevOps engineer with 15 years of experience…"
Output format constraintStructured data extraction"Respond ONLY as a JSON object with keys: title, author, year."

💡 Simple: Zero-shot just asks. Few-shot shows 2–3 examples before asking — dramatically improves format consistency. Chain-of-thought tells it to think step by step, unlocking reliable multi-step reasoning. These are not tricks; they are how you communicate intent to a statistical system that has no access to your internal goals.

Building Applications with the API
Patterns for production app development
Retry logic + error handling JS
import OpenAI, { RateLimitError, APIError } from "openai";

const client = new OpenAI();

const sleep = (ms) => new Promise(res => setTimeout(res, ms));

const callWithRetry = async (messages, model = "gpt-4o", maxRetries = 3) => {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await client.chat.completions.create({
        model, messages, max_tokens: 1024,
      });
    } catch (err) {
      if (err instanceof RateLimitError) {
        const wait = 1000 * (2 ** attempt);  // 1s, 2s, 4s
        console.warn(`Rate limited. Waiting ${wait}ms…`);
        await sleep(wait);
      } else if (err instanceof APIError && err.status === 500 && attempt < maxRetries - 1) {
        await sleep(1000);
      } else {
        throw err;
      }
    }
  }
  throw new Error("Max retries exceeded");
};
Conversation memory manager JS
class ChatSession {
  constructor(systemPrompt, maxHistory = 20) {
    this.history    = [{ role: "system", content: systemPrompt }];
    this.maxHistory = maxHistory;
  }

  async chat(userMessage) {
    this.history.push({ role: "user", content: userMessage });
    const response = await client.chat.completions.create({
      model: "gpt-4o", messages: this.history,
    });
    const reply = response.choices[0].message.content;
    this.history.push({ role: "assistant", content: reply });
    // Trim oldest user/assistant pairs if too long
    if (this.history.length > this.maxHistory + 1) {
      this.history = [this.history[0], ...this.history.slice(-this.maxHistory)];
    }
    return reply;
  }
}
💡 Simple: Three things every production app needs: exponential backoff retry logic (rate limits will hit you), a conversation history manager that trims old messages when the context window fills, and finish_reason checking to detect truncated responses before they silently corrupt your app's output.

⚠️ Edge Cases & API Gotchas
Issues that catch developers off-guard in production
HIGH
🚦
Rate Limit Errors (429)
Token-per-minute and request-per-minute limits vary by tier. Burst traffic will hit 429 even if daily quota is fine.
Implement exponential backoff with jitter. Use a token bucket / queue for high-volume apps.
HIGH
✂️
finish_reason = "length"
Model ran out of max_tokens mid-sentence. The response JSON is valid but content is incomplete. Most apps silently ignore this.
Always check finish_reason. If "length", retry with higher max_tokens or paginate.
HIGH
💉
Prompt Injection
User input contains instructions that override your system prompt. "Ignore previous instructions and…" is the classic pattern.
Use delimiters to separate instructions from user data. Validate outputs. Don't give model access to destructive tools.
MED
🌡️
Temperature + Top-p Interaction
OpenAI docs say "use one, not both". Using both can produce unexpected distributions. temperature=1 + top_p=1 = maximum randomness.
Set temperature for creative tasks, top_p for controlled diversity. Rarely change both.
MED
💰
Unexpected Token Costs
System prompts count as input tokens every call. A 2000-token system prompt at 10M calls = 20B input tokens.
Keep system prompts concise. Use the prompt caching feature (OpenAI/Anthropic) for repeated large prompts.
MED
🔒
API Key Exposure
Hardcoding keys in source code or .env files committed to git is a common security breach.
Use environment variables. Add .env to .gitignore. Rotate keys immediately if exposed. Use secrets managers in production.
LOW
🧩
JSON Mode Hallucination
response_format:"json_object" forces JSON structure but not the schema. Model may invent field names or omit required fields.
Use function calling / structured outputs (OpenAI) for strict schema enforcement. Validate with Zod.
