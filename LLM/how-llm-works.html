How LLMs Work — Complete Picture

From raw text all the way to a response in your browser — explained simply, with no assumed knowledge. Read this before any other module.

🏋️ Part 1 — Training Phase
Happens once, before you ever use the model. This is how the model learns language.
G
The One Goal of Training
Everything reduces to this

The entire training phase has one single objective:

Given the words so far → predict the next word.

"The cat sat on the ___"   →   model must predict what comes next

That's it. The model is shown billions of sentences, asked to predict the next word each time, told how wrong it was, and adjusts itself to guess better. Repeat enough times — it learns language.

💡 Analogy: Teaching a child to read by showing them billions of books. The child doesn't memorize the books — they learn the patterns of language. Same here.
1
Feed Raw Text — Tokenization
Text → numbers the model can work with

Trillions of sentences are fed in from the internet, books, Wikipedia, code, etc. But the model cannot read text — it only understands numbers.

"Paris is the capital of France"
            ↓  Tokenizer (BPE / SentencePiece)
["Paris", "is", "the", "capital", "of", "France"]
            ↓
[  4881,   318,  262,    3139,    286,    4881  ]

Numbers only. Model never sees raw text.

Tokens are not always whole words — "unhappiness" might become ["un", "happiness"]. Special tokens mark the start and end of sequences.

💡 Simple: Think of tokens as the model's alphabet. Every sentence gets converted to a list of integer IDs before the model touches it.
2
Each Token Gets a Starting Vector (Embedding)
Token ID → a list of numbers = the word's identity fingerprint

Each token ID is looked up in an embedding table — a giant lookup table where every token maps to a list of hundreds or thousands of numbers called a vector.

Token ID 4881 ("Paris")   →  [0.71, -0.32, 0.88, 0.14, -0.55, ...]
Token ID 3139 ("capital") →  [0.55, -0.12, 0.34, 0.91,  0.03, ...]
Token ID 4881 ("France")  →  [0.71, -0.32, 0.88, 0.14, -0.55, ...]

                              ↑ same token ID = same starting vector, every time

At this point the vector is just a rough identity card for the word — no context yet. "Bank" (river) and "bank" (money) both get the exact same starting vector here.

💡 Simple: Imagine each word gets a passport photo — same photo every time it appears, before context changes anything.
3
Tokens Look at Each Other — Self-Attention
This is where context shapes meaning

Every token asks every other token: "Are you relevant to me?" The answer reshapes each token's vector based on surrounding words.

Sentence: "river bank"                  Sentence: "bank account"

"bank" starting vector                  "bank" starting vector
  [0.71, -0.32, 0.88 ...]                [0.71, -0.32, 0.88 ...]
            ↓                                       ↓
  attention sees "river"              attention sees "account"
            ↓                                       ↓
  pulls in water/nature meaning       pulls in finance/money meaning
            ↓                                       ↓
  final vector ≈ river bank concept   final vector ≈ financial bank concept

Same starting vector → completely different final vector

This is the key mechanism that makes transformers powerful. The weights (numbers) in the attention layer are permanent after training. But what they produce — the activation — is different for every sentence.

Weights (Permanent)
The rules for how to reshape meaning based on context. Learned during training. Never change after training is done.
Activations (Dynamic)
The actual values produced when running your specific input through those rules. Different every single query.
💡 Analogy: The dictionary has one entry for "bank". But when you read the sentence, your brain instantly uses surrounding words to pick the right meaning. Weights = the dictionary. Attention = your brain reading context.
4
Many Layers Deepen the Understanding
Attention + FFN repeated N times

The attention + FFN block doesn't run just once. It repeats N times (e.g. 80 layers in large models). Each pass makes the meaning vector richer and more precise.

Layer 1  →  basic relationships detected ("Paris" is near "capital")
Layer 5  →  grammatical structure understood
Layer 20 →  topic identified ("this is a geography question")
Layer 50 →  intent understood ("user expects a city name as answer")
Layer 80 →  final vector: "answer needed = European capital city of France"

After the FFN (Feed-Forward Network) at each layer, a residual connection adds the original input back — so the model never completely forgets the original word, it just enriches it layer by layer.

💡 Simple: Like reading a sentence multiple times. First pass: notice the words. Second pass: notice the grammar. Third pass: understand the meaning. Each layer is one more pass at a deeper level.
5
Model Makes a Guess — Logits & Probabilities
Final vector compared against every word in vocabulary

After all layers, the final vector at the blank position is compared against every word in the vocabulary (~100,000 words). The comparison is a dot product — how similar is this vector to each word's vector?

Final meaning vector: "answer = European capital city of France"
            ↓  compare against all vocabulary words
"Paris"    →  96%    ← very similar
"Lyon"     →   1.2%
"London"   →   0.8%
"Berlin"   →   0.5%
"dog"      →   0.001%
            ↓  sample from distribution
Output: "Paris"
💡 Simple: The model doesn't look up "France → Paris" in a table. It builds a meaning vector from context, then finds which word in the vocabulary sits closest to that meaning. "Paris" wins because training nudged its vector to sit very close to "capital city of France" questions.
6
Check How Wrong It Was — Loss
The wrongness score that drives all learning

The real next word was "France". The model predicted it at 96% — not bad. But if it had said 2%, that's very wrong. This wrongness is measured as a number called the Loss.

Real next word:  "France"
Model's guess:   "France" = 96%   →  Loss ≈ small (good)

Real next word:  "France"
Model's guess:   "France" = 2%    →  Loss ≈ large (bad)

Loss formula: L = -log(probability assigned to correct word)
  -log(0.96) ≈ 0.04   ← small loss, nearly correct
  -log(0.02) ≈ 3.91   ← large loss, very wrong
💡 Simple: Loss is the score on a test. 0 = perfect. The whole point of training is to drive this number as low as possible across billions of examples.
7
Work Backwards to Find Who's to Blame — Backpropagation
Every weight gets a blame score

The model has billions of internal numbers (weights). Some contributed more to the wrong guess than others. Backpropagation works backwards through every layer using the chain rule of calculus to figure out: "how much did each weight contribute to this error?"

Loss
  ↑
Final linear layer weights        ← blame calculated here
  ↑
Layer 80 attention weights        ← blame calculated here
  ↑
Layer 79 FFN weights              ← blame calculated here
  ↑
  ... (all the way back to layer 1)
  ↑
Embedding weights                 ← blame calculated here

Every single weight gets a gradient:
  "if you increase by a tiny amount, loss changes by this much"
💡 Simple: Imagine tracing back every decision in a game to figure out which move caused the loss. Backprop does that mathematically, for every one of billions of weights, in one pass.
8
Nudge Every Weight Slightly — AdamW Optimizer
Tiny adjustments that accumulate into knowledge

Using the blame scores from backprop, the optimizer nudges every weight in the direction that would have made the guess better. The nudge is tiny — but it happens billions of times.

Before training step:   weight = 0.512
Gradient says:          "decreasing this weight reduces loss"
After optimizer nudge:  weight = 0.509   ← tiny change

Repeat for all ~7 billion weights.
Repeat for all ~1 trillion training tokens.

After billions of nudges, the weights collectively encode:
  ✓ "Paris" follows "capital of France"
  ✓ "return a + b" follows "def add(a, b):"
  ✓ medical terminology patterns
  ✓ reasoning patterns
  ✓ ...everything it was trained on
💡 Simple: Like a sculptor making millions of tiny chisels. No single chisel matters. But after enough of them, a face emerges. Training is the same — billions of tiny nudges, and understanding emerges.
✓
End Result — Frozen Trained Weights
Training is done. The brain is built.

After training, the model has a fixed set of billions of numbers that together encode a compressed understanding of language, facts, reasoning, and code. These weights are now frozen — training is complete.

What weights store
Compressed statistical patterns from everything the model ever read. Not sentences — rules for how meaning flows.
What weights don't store
Specific sentences, token IDs, or direct answers. No lookup table exists. Knowledge is distributed across all weights collectively.
Fine-tuning (separate)
A separate phase after pre-training that teaches the model how to behave — follow instructions, be helpful, stay safe. Same training loop, different data.
💬 Part 2 — Inference Phase
Every time you ask a question. Model weights are frozen — they never change here.
1
Your Question Gets Tokenized
Same process as training — text → token IDs
You type:  "What is the capital of France?"
                ↓  tokenizer
["What", "is", "the", "capital", "of", "France", "?"]
                ↓
[1234,   318,   262,   3139,    286,   4881,     30]

A chat template is applied first — your message is wrapped with system prompt, role markers, and any conversation history before tokenization.

2
Each Token Gets Its Starting Vector
From the frozen embedding table — same weights as always
Token ID 4881 ("France")   →  [0.71, -0.32, 0.88, ...]   ← same vector as always
Token ID 3139 ("capital")  →  [0.55, -0.12, 0.34, ...]   ← same vector as always

These are the PERMANENT weights.
No context yet — "France" is just "France", not yet "France the country being asked about".
3
All Tokens Processed in Parallel — Prefill
Attention reshapes every vector using YOUR specific context

Unlike generation (which is token-by-token), your entire input question is processed all at once in parallel. This is fast.

["What", "is", "the", "capital", "of", "France", "?"]
                  ↓  all 7 tokens simultaneously
"capital" sees "France" + "?" → pulls geography + question intent
"France"  sees "capital"      → activates capital-city meaning
                  ↓  after all N layers
Final vector at last position encodes:
  "user is asking for the name of France's capital city"
                  ↓
KV Cache populated:  all K,V vectors for all 7 tokens saved
💡 KV Cache: During prefill, the Key and Value vectors for every token at every layer are saved. When generating the response, the model reuses these instead of recomputing them — so the expensive part (processing your question) only happens once.
4
Sample the First Output Token
Logits → probabilities → pick a word
Final vector  →  compare against all 100k vocabulary words  →  scores (logits)
                ↓  divide by temperature  (controls randomness)
                ↓  softmax  (converts to probabilities)
                ↓  top-p / top-k filter  (cuts unlikely words)
                ↓  sample

"Paris"    →  96%   ← sampled → first output token
"Lyon"     →   1%
"London"   →   0.8%
StrategyWhat it doesWhen used
TemperatureLow = deterministic, High = creative/randomAll generation
Top-p (nucleus)Sample from smallest set of words summing to p% probabilityMost chat models
Top-kSample from top k highest-probability words onlyCombined with top-p
GreedyAlways pick the single highest probability wordDeterministic tasks
5
Autoregressive Loop — Generate Token by Token
Repeat until response is complete

The model appends the new token to the sequence and runs a forward pass for just that one new token (all prior tokens are in the KV Cache). This repeats until an end token is produced or max length is reached.

Input:   "What is the capital of France?"
              ↓  prefill (process all at once)
              ↓  KV Cache saved
Predict: "Paris"     → append → KV Cache updated with "Paris"
Predict: "."         → append → KV Cache updated with "."
Predict: <end token> → stop

Each prediction = one forward pass through all N layers
But each pass only processes the ONE new token (cache handles the rest)
→ Fast generation even for long responses
💡 Streaming: Each token is sent to your browser the moment it is sampled — that's why you see the response appear word by word, not all at once.

⚙️ Where Does the Transformer Architecture Fit?
The transformer is the shared engine — not training, not inference, but the forward pass both phases run through
T
Transformer Architecture = Steps 2 → Logits (the Forward Pass)
Everything inside here operates on token IDs and vectors — never actual words
Token IDs
    ↓  ┌─────────────────────────────────────────────────────┐
       │           TRANSFORMER ARCHITECTURE                  │
       │                                                     │
       │  Embedding lookup    →  starting vectors            │
       │  Positional encoding →  add position info           │
       │                                                     │
       │  × N Transformer Blocks:                            │
       │    Self-Attention   →  tokens look at each other    │
       │    FFN / MLP        →  enrich each position         │
       │    LayerNorm + Residual connections                  │
       │                                                     │
       │  Final linear layer →  Logits                       │
       └─────────────────────────────────────────────────────┘
    ↓
  HERE the two phases split:
  Training  →  Loss → Backprop → Weight update   (outside transformer)
  Inference →  Sampling → Output token            (outside transformer)
💡 Key point: The transformer is not training and not inference — it is the shared engine that both phases run through. What you do with the logits at the end is what separates the two phases.
!
The Model Never Sees Actual Words
Text disappears at the tokenizer and only reappears at the very end

Throughout the entire transformer — attention, FFN, all N layers — the model works exclusively with token IDs and vectors of numbers. The word "Paris" does not exist anywhere inside the model. Only its ID and its vector do.

You type:    "What is the capital of France?"
                        ↓
Model sees:  [1234, 318, 262, 3139, 286, 4881, 30]    ← token IDs only
                        ↓
Works with:  vectors of numbers throughout             ← inside transformer
                        ↓
Produces:    logit scores (still numbers)
                        ↓
Decoder:     token ID 9823  →  "Paris"                ← actual word appears HERE, at the very end

Every stage operates in a different "language":

StageInputOutputActual words?
TokenizerTextToken IDsText → gone after this
Embedding lookupToken IDsVectorsNo
Self-AttentionVectorsVectors (reshaped)No
FFN layersVectorsVectors (enriched)No
Final linear layerVectorsLogit scoresNo
SoftmaxLogitsProbabilitiesNo
Decoder (tokenizer)Token IDTextYES — first time here
💡 Simple: Think of it like a phone call. You speak words → converted to electrical signals → travels as signals the whole way → converted back to words at the other end. The wire never carries actual words — only signals. Transformer is the wire.

🧠 Three Things to Always Remember
🗄️
Weights = The Brain
Permanent numbers. Never change after training. Loaded into GPU memory and reused for every query.
⚡
Activations = The Thought
Live values flowing through the frozen weights. Change every single query based on your specific input.
🔍
Attention = Context Resolver
Uses permanent weights to reshape meaning based on current context. Same word = different meaning in different sentences.
