How LLMs Work & Text Generation

From statistical language models to deep neural networks — the conceptual foundation that every other module builds on.

1
What is a Language Model?
The probabilistic foundation

A language model is a probability distribution over sequences of tokens. Given a sequence of words, it estimates how likely that sequence is to appear in natural language.

More practically: given the tokens so far, predict the most likely next token. Repeat until done. This single idea drives all LLM behaviour.

Goal: P(w₁, w₂, w₃, ... wₙ)  — probability of a token sequence

Using the chain rule:
P(w₁...wₙ) = P(w₁) × P(w₂|w₁) × P(w₃|w₁,w₂) × ...

Practical use:
  Input:  "The capital of France is"
  Model:  P("Paris" | "The capital of France is") ≈ 0.94
           P("London" | "The capital of France is") ≈ 0.02
           P("a" | "The capital of France is") ≈ 0.001
  Output: "Paris" (highest probability)

Historical evolution:

  • N-gram models (1990s–2000s): count how often word sequences appear in training data. Simple but can't capture long-range dependencies. P("Paris" | last 2 words).
  • Neural language models (2003–2017): feed-forward networks over word embeddings. Better generalisation but still limited context window.
  • RNN / LSTM (2013–2017): recurrent networks process sequences step-by-step, maintaining a hidden state. Can handle longer context but slow to train and prone to vanishing gradients.
  • Transformer-based LLMs (2017–present): attention mechanism processes all tokens in parallel, captures long-range dependencies efficiently. GPT, BERT, T5, Llama, etc.
💡 Simple: An LLM is a very sophisticated next-word guesser. It reads your text and estimates which word is most likely next, based on everything it was trained on, then repeats that until you have a full answer. That one loop — repeated billions of times during training — is the entire foundation of all LLM behaviour.

Overview of Deep Learning
The mechanics that power LLMs
🧠
Neuron
Takes inputs, multiplies by weights, adds bias, applies activation function. Output = activation(W·x + b)
📐
Layer
A collection of neurons operating in parallel. Deep = many stacked layers. Each layer learns higher-level features.
🔥
Activation Function
Introduces non-linearity. Common: ReLU (max(0,x)), GELU (smooth ReLU used in Transformers), Sigmoid, Tanh.

Training pipeline — input to output:

Training Data                 Labelled or self-supervised (next token prediction)
      │
      ▼
  Forward Pass           Input → Layers → Prediction
      │
      ▼
  Loss Function          Cross-entropy: how wrong is the prediction?
      │                  L = -log P(correct_next_token)
      ▼
  Backward Pass          Backpropagation: compute ∂L/∂weights for each parameter
      │
      ▼
  Optimiser (AdamW)      Adjust weights: w = w - lr × gradient
      │
      ▼
  Repeat millions of     Model improves at predicting next tokens
  batches/steps          over the training corpus

Key concepts:

  • Parameters: all the weights in the network. GPT-4 has ~1 trillion. Llama-3-8B has 8 billion.
  • Gradient descent: iteratively nudge weights in the direction that reduces loss.
  • AdamW optimiser: adaptive learning rates per parameter + weight decay. Standard for LLMs.
  • Batch size: number of examples processed before a weight update. Larger = more stable gradients but more memory.
  • Learning rate: size of each weight update step. Too high → diverges. Too low → slow convergence. Warm-up + cosine decay schedule is standard.
  • Overfitting: model memorises training data, fails on new data. Mitigated by dropout, weight decay, early stopping.
💡 Simple: Think of deep learning as millions of adjustable dials. The model makes a wrong prediction and every dial nudges slightly in the right direction. After doing this on trillions of sentences, the dials are tuned well enough to write code, answer questions, and hold conversations.

LLM Training Process
Pre-training → Instruction tuning → Alignment
Stage 1: Pre-training (Self-supervised)
  ┌────────────────────────────────────────────────────────────┐
  │  Raw text corpus: web pages, books, code, Wikipedia, etc.  │
  │  Task: predict next token for every position               │
  │  Scale: trillions of tokens, weeks/months on 1000s of GPUs │
  │  Output: a model with broad world knowledge                │
  └────────────────────────────────────────────────────────────┘
                              │
                              ▼
Stage 2: Instruction Fine-tuning (SFT)
  ┌────────────────────────────────────────────────────────────┐
  │  Dataset: (instruction, response) pairs                    │
  │  Example: "Summarise this text" → "Here is the summary…"  │
  │  Output: model that follows instructions                   │
  └────────────────────────────────────────────────────────────┘
                              │
                              ▼
Stage 3: Alignment (RLHF / DPO)
  ┌────────────────────────────────────────────────────────────┐
  │  Human feedback ranks model responses                      │
  │  Reward model trained on preferences                       │
  │  PPO (or DPO) fine-tunes model to produce preferred output │
  │  Output: helpful, harmless, honest model                   │
  └────────────────────────────────────────────────────────────┘

This three-stage pipeline explains why "ChatGPT" behaves differently from a raw GPT model — it has gone through stages 2 and 3. See Module 7 for implementation details of fine-tuning.

💡 Simple: Stage 1 reads the whole internet for broad knowledge. Stage 2 shows the model good instruction-following examples. Stage 3 has humans rate responses to teach helpful, safe behaviour. ChatGPT is a GPT model that went through all three stages — raw GPT-3 did not.

Understanding Text Generation
How a model turns a prompt into output — token by token

Autoregressive generation: the model generates one token at a time. Each newly generated token is appended to the input and the model runs again. This continues until an end-of-sequence token is generated or max_tokens is reached.

Step 1:   Input: [The] [capital] [of] [France] [is]
          Model outputs probability distribution over 50,000 tokens
          Top-5:  Paris=0.94  Lyon=0.02  a=0.01  the=0.01  Rome=0.001
          Sample: "Paris"

Step 2:   Input: [The] [capital] [of] [France] [is] [Paris]
          Top-5:  .=0.61  ,=0.20  and=0.10 ...
          Sample: "."

Step 3:   Input: [The] ... [Paris] [.]
          Model outputs <EOS> token → generation stops

Sampling strategies — each changes the probability distribution:

StrategyHow it worksBest forRisk
GreedyAlways pick highest probability tokenFactual Q&A, short answersRepetitive, boring output
TemperatureDivide logits by T before softmax. T<1 = sharper (more certain). T>1 = flatter (more random)Creative writing (T=0.8–1.2)T too high → incoherent
Top-kKeep only top k tokens, re-normalise. k=50 is commonBalanced quality + diversityFixed k can be too broad or narrow depending on context
Top-p (nucleus)Keep the smallest set of tokens whose cumulative probability ≥ p. p=0.9 is commonMost production usesVery rare coherent tokens excluded near boundary
Beam searchTrack B best partial sequences at each step. Return best complete sequenceMachine translation, summarisationComputationally expensive. Often too generic
Temperature & Top-p effect on logits JS
// Softmax — pure JS (no dependencies)
const softmax = (logits) => {
  const max  = Math.max(...logits);
  const exps = logits.map(l => Math.exp(l - max));
  const sum  = exps.reduce((a, b) => a + b, 0);
  return exps.map(e => e / sum);
};

const logits = [3.0, 1.5, 0.5, 0.1];  // raw model output

// Greedy: always pick index 0 (highest logit)

// Temperature scaling
const temperature  = 0.7;
const scaledProbs  = softmax(logits.map(l => l / temperature));
// Higher peaks — more confident choices

// Top-p (nucleus sampling)
const probs      = softmax(logits);
const sorted     = [...probs].map((p, i) => ({ p, i })).sort((a, b) => b.p - a.p);
let   cumulative = 0;
const nucleus    = sorted.filter(({ p }) => {
  const include = cumulative < 0.9;
  cumulative += p;
  return include;
});
// nucleus holds the token indices that form the top-90% probability mass
💡 Simple: Temperature is your creativity dial — low for factual, high for imaginative. Top-p stops it picking bizarre fringe words by capping choices to the top-90% probability bucket. Most production apps set temperature 0.2–0.5 for facts and 0.7–0.9 for creative tasks.

Emergent Capabilities & Scaling Laws
Why bigger models behave qualitatively differently — and what you can and can't predict

Scaling laws (Kaplan et al., 2020): model performance (measured by cross-entropy loss on held-out text) improves as a smooth power law when you scale parameters (N), training tokens (D), or compute (C = 6ND). The exponents are small (~0.07 for N), meaning you need ~10× more parameters for each 16% loss reduction — expensive, but predictable.

Kaplan Scaling Law (OpenAI, 2020):
  L(N) ≈ (N_c / N)^0.076    — loss improves with more parameters (fixed data)
  L(D) ≈ (D_c / D)^0.095    — loss improves with more training tokens (fixed model)
  L(C) ≈ (C_c / C)^0.050    — loss improves with more compute budget

Chinchilla (Hoffmann et al., DeepMind 2022):
  Optimal: N and D should scale equally  →  N_opt ∝ C^0.5,  D_opt ∝ C^0.5
  Key finding: GPT-3 (175B params, 300B tokens) was *undertrained*
  Chinchilla-optimal: ~70B params trained on ~1.4T tokens beats 175B on 300B tokens
  Practical impact: Llama, Mistral, Phi models train smaller models on far more data

Emergent abilities: while the loss curve is smooth, some task metrics exhibit sharp, discontinuous jumps at certain scale thresholds. These capabilities don't gradually improve — they appear suddenly.

The 2022–2023 emergence debate: Schaeffer, Miranda & Koyejo (2023) published a provocative paper arguing that emergent abilities are a measurement artifact, not a true property of neural networks. Their argument:

  • Discontinuous metrics create false thresholds: metrics like "exact match" score 0 until the model gets the answer exactly right, then jump to 1.0. If the underlying capability grows smoothly but the metric is nonlinear, the metric will look discontinuous even though the model isn't.
  • Smooth metrics show smooth improvement: when you use log-probability or soft metrics instead of exact-match, the same capabilities show gradual improvement — no sharp threshold visible.
  • The counter-argument: Wei et al. (2022 original emergence paper) and subsequent work argue that certain reasoning tasks genuinely require a minimum parameter count to hold necessary intermediate representations — the capability truly isn't present until then, regardless of metric choice.
  • Practical stance: both can be true simultaneously. Some apparent emergence is metric-driven; some represents genuine qualitative capability shifts. Don't assume a capability exists at small scale just because you used a softer metric.

Implications for capability prediction:

  • You cannot interpolate: if a 7B and 13B model both fail a task, you cannot reliably predict when a larger model will succeed. Emergence thresholds are not predictable from smaller-scale experiments.
  • Benchmark saturation: once a model hits ~100% on a benchmark, the benchmark stops being informative. This happened with GSM8K (8th-grade math) — recent models max it out, masking differences between them. New, harder benchmarks (MATH, ARC-Challenge, GPQA) are needed constantly.
  • Compute-optimal ≠ inference-optimal: Chinchilla-optimal training maximises performance per training FLOP. But for deployment, you often want a smaller model trained on far more tokens (like LLaMA-3-8B on 15T tokens) — cheaper to serve per query, even if not maximally accurate.
  • Instruction tuning unlocks latent capability: a 7B model fine-tuned on high-quality instruction pairs can match a raw 70B model on specific tasks. The capability exists in the weights; the fine-tuning teaches the model to express it. This is why LLaMA-3-8B-Instruct outperforms raw LLaMA-3-70B on many benchmarks.
Compute budget decision tree:

Do you need to serve this model at scale?
├── Yes → train smaller, longer (Chinchilla-suboptimal, inference-optimal)
│         Example: 7B on 2T tokens  vs  70B on 200B tokens — prefer 7B for low latency
└── No  → train optimal (Chinchilla: scale N and D equally)

Fine-tuning unlocks capability:
  Raw 70B → 40% on instruction benchmark
  Raw 7B  → 25% on same benchmark

  Instruct-7B (SFT + RLHF) → 60–70% on same benchmark
  Instruct-70B              → 85%+

  → 7B-Instruct > raw 70B  (tuning > raw scale for task-specific performance)
💡 Simple: Bigger models don't just get incrementally smarter — at certain size thresholds, abilities that were completely absent suddenly appear (multi-step math, code generation, analogical reasoning). But: (1) you can't predict when this threshold will hit, (2) sometimes the "sudden jump" is just a measurement illusion caused by using binary pass/fail metrics, and (3) a smaller model that's been carefully fine-tuned often beats a larger raw model at specific tasks. Scaling up is powerful, but it's not the only lever.
⚠️ Edge Cases & Tricky Behaviours
Common failure modes when using LLMs — know these before building anything
HIGH
🌀
Hallucination
Model generates confident-sounding but factually wrong content. Root cause: language models optimise for fluency, not factual accuracy.
Use RAG (Module 4), ask model to cite sources, use low temperature for factual tasks.
HIGH
🔁
Repetition Loop
Greedy decoding gets stuck: "the the the the…". Especially bad with very low temperature or when prompt format is unusual.
Set repetition_penalty > 1.0 or use top-p sampling.
HIGH
✂️
Truncation Mid-sentence
max_tokens hit before generation completes — output cut off mid-thought.
Increase max_tokens. Check response finish_reason == "length" to detect truncation.
MED
🌡️
Temperature = 0 is not Deterministic
Even at temperature=0, floating point precision differences across hardware/versions can produce different tokens.
Use seed parameter (OpenAI supports it). Treat temperature=0 as "near-deterministic", not guaranteed reproducible.
MED
📉
Probability Degradation
As generation gets longer, probability of each token compounds. Very long outputs drift in quality. The model "forgets" the original instruction.
Break long generation into sections. Re-inject instruction for each section.
MED
🧮
Poor Arithmetic
LLMs predict tokens — they don't compute. "What is 17 × 43?" can be wrong because the answer requires calculation, not pattern matching.
Use tool calling to hand off math to a code interpreter (Module 5).
MED
📅
Knowledge Cutoff
Model training data ends at a specific date. Events after that date are unknown. Model may confidently answer with outdated information.
Use RAG to inject current data (Module 4). Include current date in system prompt.
LOW
🎭
Sycophancy
RLHF-trained models may agree with user corrections even when the user is wrong, to avoid conflict.
Prompt explicitly: "Do not change your answer based on my follow-up if you are confident."
